# SDK runner protocol

`sdk_runner.py` runs headless Claude Code sessions through the Python Agent SDK
(`claude-agent-sdk`). It is a separate long-lived process (its own systemd user
unit, its own virtualenv), so the bot stays stdlib-only and a bot restart does
not drop sessions that are waiting for a permission or an answer.

Regular background sessions (`claude --bg`, tmux, `claude attach`) are not
affected. SDK sessions are an extra kind that the bot starts on request.

## Why a separate process with an API key

- Permission requests (`can_use_tool`) and `AskUserQuestion` arrive as data, so
  the bot can show them as buttons instead of reading a terminal screen.
- The runner authenticates with an API key that never enters any process
  environment. Each session gets an `apiKeyHelper` in its flag settings: the
  command `<runner python> sdk_runner.py key --file F --var V`, which prints the
  key from the key file. The CLI runs it when it needs the key, so the agent's
  tools (Bash, hooks, MCP servers) do not inherit it. The key is never logged,
  never stored in the state file, never returned by the protocol. A plain `claude` process with
  `ANTHROPIC_API_KEY` in its environment would switch from the subscription to
  the key, which is why the key must not leak into the bot or tmux.
- Each session is checked after start: the init message must report
  `apiKeySource == "apiKeyHelper"`, otherwise the session is stopped with an
  error.

## Transport

- Unix socket, default `~/.local/state/zidos-pager/sdk.sock`, mode `0600`.
- Newline-delimited JSON, UTF-8, one connection per call (like herdr).
- Request: `{"id": "1", "method": "session.list", "params": {...}}`
- Reply: `{"id": "1", "result": {...}}` or
  `{"id": "1", "error": {"code": "not_found", "message": "..."}}`
- `events.subscribe` keeps the connection open: the first line is
  `{"id": "...", "result": {"subscribed": true}}`, then one event per line
  `{"event": "<name>", "data": {...}}` until either side closes.
- A line longer than 1 MiB is an error (`too_big`).

Error codes: `bad_request`, `not_found`, `busy`, `closed`, `no_key`,
`unavailable`, `internal`.

## Session object

```json
{
  "id": "s-1a2b3c4d",
  "session_id": "uuid assigned by the runner before start",
  "cwd": "/path/to/project",
  "name": "first line of the prompt, up to 60 chars",
  "model": "sonnet",
  "state": "working",
  "detail": "",
  "budget_usd": 1.0,
  "always": ["Write"],
  "perms": "/home/me/.config/zidos-pager/perms.json",
  "auto": [{"tool": "Bash", "what": "git status", "verdict": "allow", "rule": "Bash(git status:*)", "ts": 1760510040.0}],
  "cost_usd": 0.0123,
  "created": 1760510000.0,
  "updated": 1760510042.0,
  "pending": [ <request>, ... ]
}
```

- `id` is `s-` + 8 lowercase hex chars. The bot uses the prefix to route.
- `session_id` is generated by the runner and passed as
  `ClaudeAgentOptions(session_id=...)`, so the transcript path is known at once:
  `~/.claude/projects/<cwd with every non-alphanumeric char as "-">/<session_id>.jsonl`.
- `cost_usd` is the latest `ResultMessage.total_cost_usd` (it already includes
  earlier turns after a resume — never summed).

States:

| state         | meaning                                                         |
|---------------|-----------------------------------------------------------------|
| `working`     | a turn is in flight, nothing pending                            |
| `blocked`     | at least one pending request                                    |
| `idle`        | the turn ended normally, waiting for the next message           |
| `budget`      | `error_max_budget_usd`: resumable with a bigger budget           |
| `error`       | another error result, auth check failed, or the CLI died        |
| `interrupted` | the runner restarted while the session was working or blocked   |
| `stopped`     | stopped by `session.stop`; resumable by `session.send`          |

`detail` is a short human text for `budget`, `error`, `interrupted`.

## Pending request

```json
{
  "req": "r-5e6f7a8b",
  "kind": "perm",
  "tool": "Write",
  "tool_use_id": "toolu_...",
  "input": {"file_path": "...", "content": "..."},
  "title": "optional text from the CLI, may be null",
  "can_always": true,
  "created": 1760510010.0
}
```

- `kind` is `perm` for an ordinary permission request and `ask` for
  `AskUserQuestion` (then `input.questions` has 1–4 questions with 2–4
  options each, fields `question`, `header`, `options[{label, description}]`,
  `multiSelect`).
- `can_always` is true for every `perm` request (false for `ask`). "Always"
  is kept by the runner itself: a per-session list of tool names that it then
  allows without asking. A live probe showed that `updated_permissions` does
  not stop the CLI from calling `can_use_tool` again in SDK mode, so CLI
  permission suggestions are never applied — a button press can never write a
  settings file.
- `input` is passed as is; the bot shortens it for display.

## Methods

| method              | params                                                    | result                       |
|---------------------|-----------------------------------------------------------|------------------------------|
| `runner.info`       | —                                                         | `{"version", "sdk_version", "key": true/false}` (`key`: the key file is readable; never the value) |
| `session.list`      | —                                                         | `{"sessions": [<session>]}`  |
| `session.get`       | `id`                                                      | `{"session": <session>}`     |
| `session.start`     | `cwd`, `prompt`, optional `model`, `budget_usd`, `perms`  | `{"session": <session>}`     |
| `session.send`      | `id`, `text`                                              | `{"session": <session>}`     |
| `session.answer`    | `id`, `req`, `decision`, optional `answers`, `message`    | `{"ok": true}`               |
| `session.interrupt` | `id`                                                      | `{"ok": true}`               |
| `session.stop`      | `id`                                                      | `{"ok": true}`               |
| `session.budget`    | `id`, `budget_usd`                                        | `{"session": <session>}`     |
| `events.subscribe`  | —                                                         | stream                       |

Rules:

- `session.start`: `cwd` must be an existing directory. Defaults come from the
  runner config (`CC_SDK_MODEL`, `CC_SDK_BUDGET`; `0` = no budget limit). The reply comes right after
  the session task is created; the turn runs in the background.
  `perms` (optional) is an absolute path to the owner's `perms.json`
  (`{"sessions": {"mode", "allow", "deny"}, "chat": {...}}`, rules in Claude Code syntax). The runner reads it
  on every permission request (the `chat` section for chat sessions, `sessions` otherwise): a deny rule
  denies, an allow rule or the mode (`edits`: edits inside `cwd`; `all`: everything, never for chat) allows,
  anything else is asked as before. Each such decision is appended to the session's `auto` (last 20).
- `session.send`:
  - `idle`: a new turn in the same client (`client.query(text)`).
  - `working`/`blocked`: error `busy` (the bot tells the owner to wait or
    interrupt; nothing is queued silently).
  - `budget`, `error`, `interrupted`: a new client with `resume=session_id`
    and the text as the prompt.
  - `stopped`: like `interrupted` — a resume. `stopped` only means that no
    CLI process is running (stop, archive); the conversation stays on disk.
- `session.answer` — `decision`:
  - `allow`: `PermissionResultAllow()`; for `kind == "ask"` `answers` is
    required: `{question text: label}`, several labels of a multi-select joined
    with `", "`, a free-text answer is just the text. The runner passes
    `updated_input = {**input, "answers": answers}`.
  - `always`: like `allow`, and the tool name is added to the session's
    `always` list (persisted, kept across resumes); later requests for that tool
    are allowed by the runner without a `request.opened` event. Error
    `bad_request` if `can_always` is false.
  - `deny`: `PermissionResultDeny(message=message or "The owner declined.")`.
  - Answering an already resolved or unknown `req` returns `{"ok": true,
    "already": true}` (idempotent; two devices may press at once).
- `session.interrupt`: `client.interrupt()`; pending requests are resolved as
  deny with interrupt. The session goes to `idle` after the result arrives.
- `session.stop`: interrupt, disconnect, kill the CLI process group; state
  `stopped`.
- `session.budget`: sets a new budget; if the state is `budget`, the next
  `session.send` resumes with it.

## Events

| event              | data                                   |
|--------------------|----------------------------------------|
| `session.created`  | `{"session"}`                          |
| `session.state`    | `{"session"}` — any change of state, cost or pending |
| `request.opened`   | `{"id", "request"}`                    |
| `request.closed`   | `{"id", "req", "decision"}`            |
| `turn.result`      | `{"id", "subtype", "cost_usd", "is_error"}` |

The bot does not take text, questions or answers from events: it already reads
them from the transcript like for any session. Events are used for permission
requests (they leave no trace in the transcript until resolved), states and
cost.

An `AskUserQuestion` question is registered by the bot from the transcript (its
`tool_use` id); to answer it the bot looks up the pending request with the same
`tool_use_id` in `session.get` and calls `session.answer` with that `req`. The
bot collects the answers of all steps locally and sends them once.

## Persistence and restarts

- State file `~/.local/state/zidos-pager/sdk.json` (mode `0600`): sessions
  without the key and without message bodies. Written atomically on every
  state change.
- On runner start, sessions that were `working` or `blocked` become
  `interrupted` (their pending requests are dropped). A live probe showed that
  after `resume` the CLI treats the cut tool call as interrupted and the model
  asks for it again, so a new request appears; nothing is replayed blindly.
- Every session task always drains the message stream until `ResultMessage`
  and, on any exit path, disconnects and kills the CLI process group: when the
  Python process dies, the bundled CLI child otherwise stays alive.

## Session options

```python
ClaudeAgentOptions(
    cwd=cwd, model=model, session_id=session_id,       # or resume=session_id
    permission_mode="default",                          # never dontAsk / bypassPermissions
    setting_sources=["project"],                        # project CLAUDE.md and settings; no user hooks
    max_budget_usd=budget,
    can_use_tool=...,
    settings=json.dumps({"apiKeyHelper": helper_command}),
)
```

Live probes:
- with the key in `options.env`, `$ANTHROPIC_API_KEY` is visible to the agent's
  Bash commands, so an `env` call would put the key into the transcript;
- `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` hides it, but leaves empty placeholder
  files (`package.json`, `.env*`, `.gitmodules`, `.npmrc`, …) in the working
  directory, so it is not used;
- `apiKeyHelper`: `apiKeySource == "apiKeyHelper"`, the key is not in the
  tools' environment, no files appear.

## Configuration

The runner reads only its own environment. The systemd unit loads it from a
separate file (`~/.config/zidos-pager/sdk.env`), not from the bot's env file:
the bot's file holds the Telegram token, and everything in the runner's
environment reaches the agent's tools. `CC_SDK_SOCKET` must be the same in
both files.

The default config directory is kept on purpose: transcripts land in the
standard place, so the bot's history, forwarding and question detection work
unchanged.
